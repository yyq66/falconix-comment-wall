# 免费部署与交付

## 2026-11-24 实际部署更新

当前账号下 Render 和 Northflank 均要求绑卡，未继续使用。Hugging Face 当前新建 Docker Space 要求付费会员，也未采用。实际选择 Railway 的免绑卡免费/试用额度方案，数据库继续使用已创建并验证的 Neon 免费 PostgreSQL。

Railway 项目为 `falconix-comment-wall`，服务为 `comment-wall`。`railway.json` 指定 Docker 构建和数据库健康检查；应用通过平台提供的 HTTPS 域名访问。上传使用官方 CLI，数据库连接串通过标准输入设置为平台变量，不进入源码。额度耗尽后服务可能停止，因此提交前需要核对账户显示的剩余额度，不承诺无限期免费运行。

以下 Render 说明作为替代平台配置参考保留，实际账号如要求绑卡则不适用。

目标：Render 免费 Web Service 托管 FastAPI 和已构建前端，Neon 免费 PostgreSQL 保存数据。一个 HTTPS 地址同时提供页面、接口和 WebSocket，无需自购服务器或域名。

## 账号准备

在 Render 和 Neon 登录即可。账号注册、平台条款及必要的人机验证由账号本人完成；不需要把密码发给开发者，也不需要购买付费计划。

源码仓库采用私有仓库。Render 连接 GitHub 时仅授权这个项目，避免授权无关私有仓库。若平台要求付费或信用卡验证，应先停止并核对，不能默认为同意付费。

## 数据库

1. Neon 新建免费 PostgreSQL 项目，尽量选择与 Render 接近的区域。
2. 获取连接字符串，通常形如 `postgresql://…/neondb?sslmode=require`。
3. 将连接字符串填到 Render 的 `DATABASE_URL` 环境变量，作为秘密保存，不写入 Git。

应用会在首次启动时创建表并放入八条来自题目原型的演示评论。后续重启不重复插入，也不覆盖已保存评论。默认演示密码只用于这份考核演示，不应保存真实公司内部信息。

## 应用

在 Render 连接项目仓库，选择 New Blueprint，读取根目录 `render.yaml`。配置文件采用免费实例、Docker 构建、单后端进程，健康检查为 `/api/health`。

如果手动创建 Web Service：

- Language / runtime：Docker。
- Plan：Free。
- Dockerfile：仓库根目录 `Dockerfile`。
- 环境变量：`DATABASE_URL`、`COOKIE_SECURE=1`、`SEED_DEMO=1`、`APP_ENV=production`。
- 不增加 `--workers`，在线连接当前由单进程维护。
- 建议只在 GitHub 检查通过后自动部署。

首次构建完成后使用 Render 分配的 `https://…onrender.com` 地址。必须实际检查该地址、登录、双用户实时协作和刷新恢复，不能把“构建成功”当作部署全部完成。

## 免费额度与限制

- Render 免费 Web Service 在 15 分钟无入站流量后休眠，第一次打开可能约需一分钟唤醒；页面正常使用时的 WebSocket 心跳用于检测连接并保持在线状态。
- Render 免费实例的本地文件不持久化，本项目生产配置强制要求外部数据库。
- Neon 免费方案受计算、流量和存储额度限制；本项目当前没有外部模型调用费用。
- 平台免费规则会变化，应以创建服务当时显示的免费计划为准。

## 线上验收

两个独立浏览器会话分别登录 `demo_a` 和 `demo_b`（默认密码 `Wall2027!`）：

1. 在线成员互相可见。
2. A 发便签，B 不刷新出现；A 编辑和移动后 B 同步。
3. B 点赞 A 的便签，双方数量同步；重复点赞不会重复计数，可取消。
4. B 只能查看 A 的便签，不能编辑或移动；服务端也拒绝直接越权请求。
5. 刷新、重新登录及服务重新部署后，已保存内容、位置、点赞仍在。
6. 编辑内容会重新分类情绪，占比及时更新；智能整理分列且不写共享位置，可还原。
7. 断开网络再恢复，状态自动补齐；退出后在线列表更新。
