# 情绪分类与配置

优先使用配置的大模型 API；未配置、超时、限流或输出无效时，使用之前的中文规则。只显示正向、负向、中性三类，不使用本地神经网络模型。

## 大模型 API

在 Railway 后端环境变量（或本地 `.env`，启动时加 `--env-file .env`）设置三项：

```dotenv
SENTIMENT_API_BASE_URL=https://your-provider.example/v1
SENTIMENT_API_MODEL=your-model-name
SENTIMENT_API_KEY=your-secret-key
```

服务使用 `{base_url}/chat/completions`，要求支持 JSON 对象输出。兼容该协议的提供商可使用相应地址和模型名；密钥仅在后端读取，不进入前端、Git 或评论数据。改变配置后重启服务。当前交付环境没有配置真实 API 密钥，因此默认实际使用规则；API 路径由模拟 HTTP 服务验证，没有产生付费模型调用。

只发送评论正文，不发送作者、头像、账号、点赞等信息。系统提示规定三类评价倾向，并将评论作为数据传入。接口超时为 6 秒，失败后 60 秒内跳过接口并使用规则，之后新请求可尝试恢复。

## 原中文规则

恢复 `00378a4` 版本的词库和评分方式，代码在 `backend/sentiment_rules.py`：

- 匹配正向词（如感谢、好用、满意）加一分，负向词（如很差、闪退、失望）减一分。
- 处理紧邻词语前的否定表达，如「不是很好」。
- 按标点及转折词分句累加，最后一个分句在存在多个分句时权重为 1.5。
- 得分大于 0.5 为正向，小于 -0.5 为负向，其余为中性。

这是轻量规则，不具备完整语义理解；未覆盖的表达、反讽、复杂转折和相互抵消的倾向可能归为中性或误判。此版按用户要求保持之前的规则，不以额外状态替代中性。需要更好的语义判断时可配置大模型 API。

规则不需要下载模型、显卡或额外推理库。Docker 镜像已移除 ONNX Runtime、分词器和权重下载步骤。

## 结果保存与迁移

分类结果、来源和配置签名与评论正文版本一起保存。只在发表/修改时计算；相同请求重试、移动、点赞、浏览不重复调用接口。配置签名改变后，启动时重新分类旧评论，保留正文、位置、时间、点赞和版本号；历史本地模型结果会自动更新为三类规则或 API 结果。

验收覆盖 API 优先、无配置使用规则、超时/限流/无效输出回退和恢复、原规则行为、结果保存，以及旧模型结果迁移后评论数据保持不变。
